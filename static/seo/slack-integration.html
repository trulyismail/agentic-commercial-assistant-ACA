ACA + Slack — validate a lead without opening a browser

A sales team that already lives in Slack should not have to open a separate tool to approve a lead. ACA's Slack alert is not a notification with a link back to the app — it carries real interactive buttons (Block Kit), and clicking one resumes the paused analysis directly.

How it works

  1. send_approval() posts the analysis summary with "✅ Valider"/"✕ Rejeter" buttons, the lead's thread_id carried in the button's value.
  2. A click POSTs to /slack/interactions, which verifies Slack's HMAC-SHA256 request signature — the endpoint fails closed (503) if the signing secret is not configured, rather than accepting an unverified click.
  3. The same _do_validate/_do_reject helpers back both this endpoint and the REST API, so a Slack approval and a dashboard approval write identically to the audit log and the CRM.
  4. If Slack is not configured, the alert falls back to a plain e-mail — buttonless, but the human gate still fires.
The Slack alert itself is live-verified (a real message delivered to a real workspace channel). The interactive-button callback loop is covered by 36 automated tests building genuinely HMAC-signed requests — approve, reject, bad signature, unconfigured secret — but has not been exercised against a real Slack app's Interactivity feature, which needs a public HTTPS endpoint this project does not currently have.
