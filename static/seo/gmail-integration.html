Integration

ACA + Gmail — inbox intake, drafts in-thread

Most "AI email" tools bolt on a forwarding rule and call it an integration. ACA authenticates directly against the Gmail API (OAuth, an installed-app client, scope gmail.modify) and does three things a forwarding rule cannot: it reads every attachment on a message, not just the body; it drafts the reply inside the original thread, with the correct threadId and In-Reply-To headers, so a human sees one continuous conversation instead of a new stray message; and it never sends anything itself — the draft sits in Gmail exactly where a person would leave one for themselves.

How it works

  1. list_unread_emails() polls the inbox — via poller.py in the background, or a manual "check now" in the UI.
  2. get_email() pulls the body and walks every MIME part recursively to collect PDF, Word and Excel attachments — not just the first one found.
  3. The extracted text (email + every attachment, capped once at 15,000 characters combined, not per file) feeds the classification and drafting pipeline.
  4. On approval, create_draft_reply() creates the Gmail draft in-thread. mark_as_processed() removes the UNREAD label and adds an ACA-Traité label so the same email is never re-queued.
Live-verified end to end, including the multi-attachment path (synthetic PDF + Word + Excel in one email, all three extracted, an unsupported extension silently skipped) and the draft-reply thread headers.
