What is an agentic workflow?

An agentic workflow is a pipeline in which a language model participates in deciding what happens next, not merely what text to produce. The test that separates it from a plain "call the model and use the output" script: does control flow depend on a model's judgement at runtime, or is every step fixed in advance regardless of what the model says?

A single prompt-and-response call is not agentic, even a very good one. Feeding a chatbot's output into the next fixed step is not agentic either — that is a pipeline with a language model in it, not a workflow the model steers.

ACA's implementation is a concrete instance: a supervisor node (a small model) reads what has been done so far and decides which specialised worker to call next — enrichissement (company research), connaissance (retrieval from a knowledge base), veille (a web-search fallback), or stratege (the drafting model) — from a real decision space, not a fixed sequence. Deterministic guardrails narrow that space where a choice genuinely shouldn't be left to the model (a spam email never reaches the drafting worker; the drafting worker is always the final step) — agentic does not mean unconstrained, it means the model's judgement genuinely changes the path taken.

The supervisor's routing logic and its deterministic guardrails are exercised by unit tests covering each branch (SPAM/AUTRE/SUPPORT skip straight to FINISH, veille is forced after an empty connaissance result, stratege is never repeated).
