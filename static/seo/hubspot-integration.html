Integration

ACA + HubSpot — a real CRM write, behind a human gate

HubSpot is the CRM most of ACA's prospects already run — so ACA writes to it directly rather than asking a team to copy leads out of a spreadsheet. The write is real (Contact, Deal, Note, all three genuinely associated via HubSpot's v4 API), and it happens exactly once, only after the validation gate.

How it works

  1. On "Valider", create_lead() searches HubSpot for an existing Contact by e-mail — patches it if found, creates it if not.
  2. A Deal is created in the configured pipeline/stage (defaults to any fresh portal's "default"/"appointmentscheduled") and associated to the Contact.
  3. Urgency, stated need and the drafted proposal are attached as a Note — Deals carry no free-text field by default.
  4. Sheets is written in the same step, not replaced by it: Sheets stays the duplicate-detection memory (find_leads_by_sender) and the dashboard's data source.
Live-verified against a real HubSpot portal: contact, deal, note and associations all created correctly, then deleted as test cleanup. A real bug was caught during that verification — a Windows console encoding crash after a successful write, which the graph's retry policy would have turned into a duplicate write — fixed by making the write's return value never depend on a print succeeding.
