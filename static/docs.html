01 — Overview

What you're installing.

ACA pre-reads incoming sales email and its attachments (PDF, Word, Excel), extracts the lead's information with an LLM, checks it against your own knowledge base, drafts a proposal — then stops. Nothing reaches your CRM and no email goes out until a person clicks "Validate". It drafts and waits; it never acts alone on your CRM.

One deployment, one tenant, on your infrastructure: your Google Sheet, your API keys, your container, your data. What you start is four processes, all launched by one command:

ProcessRoleFile
APIThe brain over HTTP — exposes the graph, drives the UI, Slack and n8naca/api.py
UIThe operator console — intake, validation, settings, dashboardui.py
PollerWatches the Gmail inbox and starts an analysis for each new messageaca/core/poller.py
SchedulerFollow-ups, GDPR purge, archives — on a fixed cadenceaca/core/scheduler.py

Two tiers, and n8n is never required for automation:

TierComponentsFor whom
SoloAPI + UI + poller + schedulerSolo consultant, SMB — automated end to end, no n8n
EnterpriseSame, plus n8nOrchestration with your other tools (CRM, ERP, ticketing)

Both tiers run the same image and the same API: n8n is additive, it replaces nothing.

02 — Before you start

What you need.

The project's guiding principle: an absent configuration variable means "feature skipped", never a crash. So the list below separates what is genuinely required from what is merely nice to have.

Strictly required

  • Python 3.11 or newer (built and tested on 3.14).
  • A Google account to create a Google Sheet in — it is the CRM and the knowledge base.
  • A Google service account (free) with the Google Sheets API enabled, so the code can read and write that sheet without a human in the loop.
  • A free Groq API key (console.groq.com) — the one account you strictly need for a real analysis to run: classification, extraction, supervision and drafting all depend on it.

Useful, but optional

  • A free Gemini key — enables semantic search over your knowledge base. Absent, the system falls back to keyword search instead.
  • A free Tavily key (1,000 requests/month) — automatically enriches a prospect's company profile and acts as a fallback when your FAQ has no answer.
  • A Gmail account — for automatic email intake, reply drafts and follow-ups. The first run opens a browser for consent; it is a one-time, local step.
  • Git, to fetch the repository (a ZIP archive works too).

Everything past this point — HubSpot, Slack, Supabase, n8n, Stripe — is added later without breaking anything. Every integration degrades cleanly in its absence: see §09 "Optional integrations".

03 — Try it, no install

Try it before you install anything.

Demo mode runs the real graph — same supervisor, same self-critique, same validation pause — with a simulated model and no API key at all. Only the billable call is simulated; CRM writes are hard-blocked, not merely skipped.

Without installing anything locally

If a hosted demo instance is available, the "Open the demo" button on the pricing page leads straight to it.

Locally, in one command

After the first three commands of the next section (clone, virtual environment, dependencies):

python -m aca.core.app # runs 6 mock emails through the full graph, stops at the validation pause, # never writes anywhere — no .env file needed at all

To see the same thing from the Streamlit console (the example-email picker, the dashboard, the settings screen) rather than the command line:

copy .env.example .env # Windows — cp on macOS/Linux # open .env and set: ACA_DEMO_MODE=1 streamlit run ui.py

In demo mode, demo.guard_write() raises rather than silently skipping a CRM write attempted by mistake — the deliberate exception to the rest of the project's graceful degradation, because a fake row written into a prospect's CRM during a demo is an incident, not a shrug.

04 — Five commands

From zero to a running instance.

For a real analysis (not the demo), you will need a Google service account and a Groq key — see §02. The rest of this section assumes both are ready.

1. Create the Google Sheets service account

  1. In the Google Cloud Console, create a project, enable the "Google Sheets API", then create a service account and download its JSON key.
  2. Save that file as credentials/service_account.json at the repository root.
  3. Create a new Google Sheet, then share it with "Editor" access to the service account's email address (the client_email field in the JSON file).
  4. Copy the sheet's ID — the long string between /d/ and /edit in its URL.

2. Install and configure

git clone <repository-url> aca && cd aca python -m venv venv && venv\Scripts\activate # Windows; source venv/bin/activate elsewhere pip install -r requirements.txt copy .env.example .env # Windows; cp on macOS/Linux # open .env and fill in GROQ_API_KEY and GOOGLE_SHEETS_ID from step 1 python scripts/setup_sheets.py # once — creates the "Leads" header row python scripts/setup_faq.py # once — seeds the FAQ with 74 sample Q&A pairs

3. Start it

python scripts/run_solo.py # API + UI + poller + scheduler, together, one Ctrl+C stops all four

The UI is at http://localhost:8501, the API at http://localhost:8000 (health check: /health).

These five commands are the strict minimum. A variable left blank in .env crashes nothing: the capability it gates is simply skipped, as long as ACA_ENV stays on development (the default) — see §10 for what changes in production.

Nearly everything in groups 2 through 9 can also be set without touching .env, from the "Settings" screen in the UI — see §08. .env stays useful for starting everything already configured (a Docker image shipped already in a client's colours, for instance).

06 — Docker

The same container, two profiles.

One image for all four services, and two Docker Compose profiles — solo (API + UI + poller + scheduler) and enterprise (same, plus n8n). It is the concrete proof that n8n is optional: both profiles run the same image and the same API; the orchestrator is removed by changing one word.

docker compose --profile solo up # without n8n docker compose --profile enterprise up # with n8n

Google credentials are mounted read-only and never copied into the image; a named volume keeps the local SQLite registries (queue, audit log, accounts, scheduler) — without it, validating a lead and then restarting the container would lose the trace. Ports are bound to loopback (127.0.0.1) by default: exposing this publicly needs TLS and a mandatory API key, see §10.

Without Docker, the Solo tier starts with one command — see §04, step 3.

07 — First login

Create your first account.

With no named account created, the UI falls back to the shared ACA_UI_PASSWORD if one is set, or stays open otherwise — fine for a local trial, not for a team. Create a named admin account as early as possible:

python -m aca.storage.user_store create alice --role admin

Then sign in. admin accounts require a second factor (TOTP): the first login shows a QR code — scan it with any authenticator app (Google Authenticator, Authy, 1Password…) and enter the 6-digit code once to confirm enrollment.

RoleCan do
adminEverything: settings, accounts, knowledge-base curation, second factor mandatory
operatorThe day-to-day work: validate or reject leads
viewerRead-only: dashboard and history

Other useful commands:

python -m aca.storage.user_store list python -m aca.storage.user_store passwd alice python -m aca.storage.user_store disable alice
08 — Make it yours

Your colours, no restart.

From "Settings → Appearance" (an admin account), logo, palette, typography, corner radius, density and animation level are all set without touching a line of code and take effect immediately — no restart, no redeploy.

The same screen also manages the Calendly booking link appended to proposals, the support/HR routing addresses, and the follow-up cadence — settings that used to live only in .env.

10 — Going to production

What changes in production.

The whole project runs on graceful degradation — "absent = feature skipped" — the right default locally, and exactly the wrong one on a public host, where it becomes "absent = exposed". ACA_ENV is the explicit switch:

ACA_ENV=production

refuses to start if ACA_API_KEY, a login gate, ACA_RATE_LIMIT or ACA_METRICS_TOKEN is missing — instead of development mode's "absent = open".

Checklist before opening this up publicly

  1. Put it behind TLS — ready-made Caddy/Nginx configs, including the WebSocket headers Streamlit needs, live in docs/DEPLOYMENT_HARDENING.md.
  2. Run python -m aca.core.prod_check — checks the security posture without ever raising, the same check behind the UI's admin-only banner.
  3. Decide the retention window (RETENTION_DAYS, default 365) and confirm the scheduler's purge job is enabled.
  4. Run the read-only Supabase RLS sweep: python scripts/verify_rls.py.
  5. Read docs/PRIVACY_POLICY.md before the first real prospect email arrives.
11 — Verify it works

Trust, then verify.

python -m pytest tests/ # full offline test suite python -m aca.eval.eval_classifier # classifier accuracy on 50 labeled emails python scripts/verify_rls.py # Supabase RLS coverage, read-only python -m aca.storage.audit_log # checks the audit log's hash chain curl http://localhost:8000/health # liveness — no secret, no external call

The test suite runs fully offline — no real key is required to run it — and tests/conftest.py neutralises every external integration before any import happens.
